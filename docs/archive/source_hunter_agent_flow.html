Source Hunter Agent Flow

A focused diagram for the URL-discovery agent: how it searches, fetches, validates, rejects bad pages, retries, and hands only adequate evidence to the answer model.

What This Agent Is Doing

The agent is not just asking a model to browse. It is a controlled loop around search and scraping. The loop keeps looking until it finds a page that contains the evidence needed to answer the question, or until the budget runs out.

Input

Evidence Contract

The question is converted into a generic or generated contract: entity, date, document type, required answer slots, official-source preference, and weak-page traps.

Loop

Search And Fetch

The discovery model proposes candidate URLs. The harness fetches the pages directly, extracts readable text, and builds source excerpts.

Output

Validated Evidence

Only accepted pages are passed to Gemma, GLM, Gemini, or whichever answer model is being benchmarked. Rejected pages never become answer evidence.

Flowchart

The important behavior is the red feedback path: when a URL is missing, stale, blocked, or not evidentially adequate, the agent records why and asks the search step to avoid that mistake.

Validation Gates

The gate is the brain of the source-hunter. It checks whether a page satisfies the generated or generic evidence contract, not merely whether it is topically related.

1
Fetch ValidityReject if the URL 403s, 404s, times out, redirects to login, or extracts no useful text.
2
Constraint MatchHard-check exact date, named entity, item number, advisory time, document type, and official-source requirement.
3
Evidence AdequacyRequire the page to contain the slots the answer needs: counts, vote, range, warning area, motion, pressure, dollar amount, or table rows.
4
Weak-Page RejectionReject previews, calendars, agendas without item text, press-event announcements, secondary copies, recaps, and stale pages.

What Happens When URLs Fail

Failures are not all the same. The source-hunter records the specific reason, then retries broadly or stops safely. Site-specific resolvers are optional adapter mode, not the clean benchmark default.

Failure Type Example Agent Response Safe Outcome
Fetch failure 403 on Riverside HWS or HARI page Mark fetch_failed, keep looking for official mirrors, PDFs, archived pages, or related county pages. If no valid source is found, answer should abstain or state the source gap.
Wrong document Legistar calendar page instead of meeting item detail Reject as document_mismatch; optional adapter mode can try a Legistar meeting-detail resolver. Only agenda detail pages with the right date and item number are accepted.
Related but insufficient Webinar or preview announcement before results are posted Reject as missing generated result slots, then search for an official page with the actual release. No hallucinated counts from a page that lacks numbers.
Secondary copy LegiStorm copy of Federal Reserve statement Reject when official source is expected; optional adapter mode can try a Fed calendar/statement resolver. Answer cites federalreserve.gov.
Nearby official page NHC storm archive or mobile advisory with wrong timestamp Reject on time mismatch, crawl official NHC archive table for exact UTC advisory. Answer uses the exact advisory.
Dynamic or awkward HTML Government portals where search finds listing pages but not item pages Use controlled fetch first; add reader/browser-rendered fetch if static extraction cannot see the text. Evidence gate still decides whether the rendered page is enough.

What Is Generalizable

The exact benchmark URL is not the general solution. The portable solution is the generated source contract, stale-page checks, controlled fetch, validation, and retry loop. Site-specific resolvers are opt-in accelerators for recurring public systems.

Generalizable

The Contract And Gate

Any question can be converted into required evidence slots by a generated contract or a generic fallback parser. Any candidate source can be checked against those slots. This works across city councils, agencies, weather advisories, public health releases, court filings, PDFs, and local news pages.

Core rule: a source is not found until it contains the answer evidence.

Site-Specific

Resolvers

Resolvers are small helpers for known weird systems: Legistar, NHC archives, Federal Reserve calendars, county press-release paths. They should not replace validation. They just propose better candidate URLs.

Core rule: if optional adapters are enabled, a resolver can suggest a page, but validation still has veto power.

Production direction: add generic official-domain search, sitemap/news/press-page crawling, browser-rendered fetch for dynamic pages, PDF extraction, then use specific resolvers only when the public site structure is stable and valuable enough to encode.
