End-to-End Map

The scheduled Raspberry Pi run starts in main2.bash. It calls main.py for gather, scripts, and audio, then moviemaker.py, then uploader2.py.

Idempotent stages

Gather and script generation use marker files and existing outputs to skip completed work. Failed slots can be absent without killing the whole episode.

Topic Selection

After collecting headlines, the system removes or tags repeat coverage, scores candidates on four newsworthiness criteria, researches the strongest candidates with grounded search, then chooses the episode structure.

1. Headline bundle NPR, AP, Democracy Now, ProPublica, CalMatters, and Riverside headlines are concatenated into one source-labeled document.
2. Dedup / arc filter Compares against the story ledger when available; otherwise checks the past seven days of story summaries.
3. Tier 1 scoring Asks for one 1-10 score per headline, sorted highest to lowest, then keeps the top ten parsed headlines.
4. Tier 2 research Runs a grounded Gemini Flash brief for each shortlisted headline and assembles those briefs into one research document.
5. Tier 3 picks Chooses the national lead, California/everyday lead, and overview headlines from the research document.

Dedup / arc filter

  • This is a repeat-management pass, not a numeric scoring pass.
  • If story_ledger.json has active arcs, the LLM sees each arc slug, topic, last-covered date, and audience state.
  • If the ledger is empty, it falls back to load_recent_story_descriptions(window_days=7).
  • Each headline is classified as SAME STORY, NO NEW INFO, UPDATE, MAJOR ESCALATION, or NEW STORY.
  • SAME STORY, NO NEW INFO is removed. Updates and escalations are kept with tags such as [UPDATE: arc_slug].

Tier 1 scoring

  • Model call: get_llm_response(..., mode="standard"), which routes to Gemini Flash without web tools.
  • Score format: SCORE: X | HEADLINE: Y | REASON: Z.
  • Criteria: impact scale, institutional response, novelty, and accountability.
  • Tagged [UPDATE] and [MAJOR ESCALATION] stories are not penalized just for being continuations; the new development is scored.
  • If fewer than five score lines parse, the code falls back to passing all non-empty headline lines forward.

Tier 2 grounded briefs

  • For each shortlisted headline, TIER2_RESEARCH_PROMPT asks for a 150-250 word newsroom memo.
  • Model call: get_llm_response(research_prompt, grounding=True, mode="standard").
  • Router target: Google Gemini gemini-3-flash-preview with Google Search grounding.
  • The memo must cover what happened, context/history, impact/scale, and which major outlets are reporting it.
  • If verification fails, the response should begin with UNVERIFIED: and explain what was tried.

Tier 3 final picks

  • Important story: mode="heavy", no web tools, selected from the Tier 2 research document.
  • Everyday/California story: also mode="heavy", excluding the already chosen important story.
  • Router target for those heavy calls: Claude Opus via the Anthropic adapter.
  • Overview picks: mode="standard", excluding the two main stories and related stories.
  • Main-story prompts reject ordinary [UPDATE] stories but allow [MAJOR ESCALATION]; overview picks may include updates.

Selection outputs

  • stories_chosen/{date}_stories_chosen.txt stores selected main topics.
  • stories_chosen/{date}_story_summaries.json stores archive summaries for future deduping.
  • stories_chosen/story_ledger.json stores arcs and audience state.
  • segment_summaries/{date}_GATHER_MANIFEST.json pins the exact topic picks for reruns.

Per-Topic Research

Once two main topics are selected, each topic gets a separate deep-dive. The first pass builds a seed evidence bundle from articles and grounded search. Then a LangGraph research agent decides what else to ask or fetch before the final super-summary is synthesized.

Google Custom Search details

google_official_search() uses Google CSE, filters social/blocked hosts, and asks the LLM to rewrite the query when no results come back.

Article extraction

scrape_text() strips page chrome, tries article containers, falls back to normalized body text, and truncates at 20,000 characters.

Adaptive research

run_adaptive_research() replaces the fixed eight-round follow-up loop when AGENTIC_RESEARCH_ENABLED is true. The old loop remains as an emergency fallback.

Final synthesis

The final super-summary generation stays deterministic. The agent enriches summary_prompt; then the existing synthesis prompt writes the researched story summary.

Agentic Research

The selected-story research agent is a bounded LangGraph state machine. It does not replace the LLM router, search wrapper, scraper, RAG store, or final synthesis. It only decides the next research action for the two main stories.

Public entrypoint

run_adaptive_research(topic, slot, date, date_key, summary_prompt, article_count, articles, followups) returns an enriched prompt plus updated article and follow-up accumulators.

State fields

The graph carries topic, formatted_date, summary_prompt, articles, followups, memory_note, iteration counts, failure counts, and the last controller decision.

Controller inputs

The controller is the main agent brain: get_llm_response(..., mode="heavy"), routed to Claude Opus 4.8. It sees the story topic, current evidence, RAG memory note, recent Q&A, article count, completed iterations, minimum iterations, and remaining budget.

What it optimizes for

The prompt asks it to think like an investigative reporter: central claim, source quality, missing timeline, scale, mechanism, counterevidence, freshness, and accountability.

Continue: grounded search

Used for precise questions. The answer is produced by get_llm_response(question, mode="light", grounding=True) and appended to the research prompt.

{
  "status": "continue",
  "action": "grounded_search",
  "question": "What is the strongest evidence for or against the central claim?",
  "question_type": "premise_challenge",
  "reason": "The claim is important but not yet stress-tested."
}

Continue: article search

Used when the evidence is thin and a new article is likely to help. It calls google_official_search(), then result_piper() keeps at most one new relevant article per iteration.

{
  "status": "continue",
  "action": "article_search",
  "query": "headline terms official response local reporting",
  "reason": "Need another source before synthesizing."
}

Done decision

The controller can stop once the minimum iteration rule is satisfied. If it says done too early, the code forces one freshness-check grounded search.

{
  "status": "done",
  "reason": "Enough independent sourcing and no major unresolved claim.",
  "confidence": "medium"
}

Failure behavior

  • Malformed JSON gets one repair call.
  • Tool failures are logged and do not append bad Q&A.
  • Two consecutive controller/tool failures stop the graph gracefully.
  • If graph setup or execution fails before useful output, _gather_one_topic() falls back to the old fixed follow-up loop.

Question types

premise_challenge, scale_check, source_check, timeline_check, mechanism_check, counterevidence_check, and freshness_check.

Sidecar metadata

Research-agent follow-ups keep the old fields and add optional metadata: iteration, question_type, action, reason, and memory_guided.

Config switches

AGENTIC_RESEARCH_ENABLED=True, AGENTIC_RESEARCH_MIN_ITERATIONS=2, AGENTIC_RESEARCH_MAX_ITERATIONS=5, and RAG_RESEARCH_MEMORY_ENABLED=True.

RAG Implementation

RAG is implemented as research memory. The write path captures article summaries and research-agent Q&A into a SQLite vector index. The active read path retrieves prior chunks before adaptive research and turns them into a dated memory note. A separate late summary-refine path still exists, but remains disabled by default.

What gets indexed

Each sidecar becomes chunks. Article chunks store source, headline, URL, and article summary. Research Q&A chunks store Q: ... A: ... text, including agent metadata when present.

Where vectors live

ResearchIndex stores metadata and float32 vectors in SQLite. Search loads rows, normalizes vectors, computes cosine similarity with NumPy, and returns top hits.

Active read path

RAG_RESEARCH_MEMORY_ENABLED = True enables early retrieval. The query is selected topic plus current seed evidence. Retrieved chunks become a memory note for the LangGraph controller.

early memory on

Fail-safe behavior

If memory retrieval or memory-note generation fails, the research agent continues without memory. If late refinement fails, the pipeline keeps the original super-summary.

never blocks gather

Early memory note

build_research_memory_note() retrieves prior chunks with exclude_date=today, then asks Claude Opus 4.8 for four sections: prior background, possibly stale facts, unresolved questions, and suggested search targets.

Late summary refinement

_augment_with_prior_research() still exists after super-summary generation, but RAG_AUGMENT_ENABLED = False keeps it off by default. This avoids old research rewriting current facts unless explicitly enabled.

Core rule: prior coverage can guide questions, but today's sources must verify current facts. The RAG memory note is context for the controller, not evidence that automatically goes into the final story.

Script, Audio, Video, Upload

After gather, summaries become dialogue scripts, then TTS audio, then an MP4 with a static image, then a public YouTube upload.

Scripts

  • story_gatherer() reads available slot summaries.
  • headline_maker() creates show headlines.
  • intro_writer() writes intro text and episode title.
  • segments_writer() drafts Grace/reporter dialogue and scores candidates.

Audio

  • google_speak() uses Google Cloud TTS voices for Grace, Ethan, Chloe, and Elias.
  • Line-level WAV files are assembled into per-segment MP3 files.
  • Intro music is overlaid with PyDub.
  • assemble_podcast() exports normal and HQ MP3 files.

Video

  • create_video_from_audio_and_image() combines output_audio/{date}_HQ.mp3 with image copy.png.
  • The result is output_video.mp4.

Upload

  • uploader2.py reads the episode title file.
  • Gemini creates tags from the description.
  • YouTube Data API uploads with OAuth credentials.

LLM Router

get_llm_response() centralizes model choice, retry policy, grounding support, URL fetch support, and fallback behavior.

Mode / flags Primary provider Primary model Used for
light, no web tools Google Gemini gemini-3.1-flash-lite Fast helper tasks, yes/no relevance, query cleanup, title extraction.
standard, no web tools Google Gemini gemini-3-flash-preview Tier 1 scoring, super-summary synthesis, overview writing, and other non-agent standard tasks.
light or standard with grounding or url_context Google Gemini gemini-3-flash-preview Fresh web search, URL page context, headline discovery, grounded briefs, and research-agent grounded answers.
plus or heavy with web tools Google Gemini gemini-3.1-pro-preview Higher-quality web-assisted reasoning when grounding or URL context is required.
heavy, no web tools Anthropic via app adapter claude-opus-4-8 Research-agent controller decisions, RAG memory notes, final story selection, and long dialogue script writing.
Primary exhausted or auth failure OpenRouter fallback openai/gpt-5.5 Fallback call; attaches openrouter:web_search and/or openrouter:web_fetch when the original request needed those tools.
